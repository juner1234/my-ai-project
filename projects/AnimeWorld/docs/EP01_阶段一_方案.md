## 一、现有 Spine 动作能力核查

核查对象：`public/characters/test/spine/skeleton.json` + `src/spine/*`（`loadSpine.ts` / `spineEval.ts` / `RealSpinePlayer.tsx`）。

### 1.1 播放器真实能力
| 支持 | 不支持（会显式警告，不静默） |
|---|---|
| region 附件（整层 PNG） | mesh 顶点网格 |
| 骨骼 translate / rotate / scale 时间轴，linear 插值 | deform / draw-order / IK / transform / path 约束 |
| slot 遮挡顺序（draw order） | slot 颜色时间轴 |
| 姿态 = 帧的纯函数（逐帧可复现） | bezier 缓动（近似 linear 并上报） |

### 1.2 导出骨架实况（关键）
1. **`animations` 为空 `{}`**——导出里一个关键帧都没有。当前 Studio 靠 `RealSpinePlayer` **注入的测试动作**（头部摆动 + 呼吸）来演练骨架。这是"当前能力"，不是角色自带动画。
2. **骨骼清单**：`root / rig_root / torso / neck / head / eyes / leftArm·rightArm / leftElbow·rightElbow / leftLeg·rightLeg / leftKnee·rightKnee`。
   - 但 Q 版素材**没有可分离的手臂/腿层**（手、腿分别烘焙进 `handwear` / `legwear` / `topwear`），所以四肢骨**当前无实际可动层**。
3. **层绑定**：eyewhite / irides / eyelash / eyebrow / ears / legwear / handwear 导出时绑在 `root`（不跟头）。`loadSpine.ts` 已在加载期**重绑到 head 并保持静止姿态**，并修正了 eyelash/eyebrow 被 face 遮挡的绘制顺序（`docs/spine-smoke.md` 已记录）。
4. **伪影层**：`neckwear` / `headwear` 为模型误判残留，加载时**丢弃并上报**。

### 1.3 本集可用 / 不可用动作（结论）
| 需求文档提到的动作 | 结论 | 实现方式 |
|---|---|---|
| 呼吸 | ✅ 可用 | `torso` scale |
| 歪头 | ✅ 可用 | `head` rotate（单侧倾） |
| 摇头 | ✅ 可用 | `head` rotate（左右交替） |
| 轻微点头/抬头 | ✅ 可用 | `head`/`neck` rotate |
| 整体入场/位移/缩放 | ✅ 可用 | `rig_root` translate / scale |
| **眨眼** | ❌ **不支持** | 眼睛层本身就是**闭眼笑（^ ^）**，无睁眼素材；`eyelash` 只是深棕睫毛笔触，`irides` 是闭眼弧线 + 高光点 |
| **睁大眼睛 / 眼神变化** | ❌ 不支持 | 同上，无对应图层 |
| **微笑 / 表情切换** | ❌ 不支持 | 表情为**固定层**（闭眼 + 小张嘴），无表情库，且硬性限制禁止补画表情 |

> **重要影响**：需求文档分镜中多处"表情/眼神"描述（如"软软笑""脸"变化）**必须删除或改为身体语言表达**（歪头、轻微点头、呼吸、纸页/道具动作），不得声称已实现。已按此在 §六 列出需要改写的分镜点。

**阶段一未做**：未修改任何骨骼/素材/播放器，未触碰 `AnimeWorldTest`。

## 二、统一美术规范（以现有暖暖画风为基准）

分析依据：`public/characters/IMG_5091.JPG` 与 `clean/` 全部图层（front_hair / face / topwear / legwear / mouth / eyelash / irides 等）。

### 2.1 画风观察
- **线条**：细、软、略带铅笔/蜡笔颗粒与**轻微模糊/晕染边缘**；轮廓**不用纯黑**，偏暖褐/浅棕。
- **上色**：低饱和**水彩 + 彩铅**渐变；边缘柔和晕开，局部留白高光（如发丝、眼高光、裙边）。
- **比例**：Q 版约 **2.5–3 头身**，头大身短。
- **气质**：粉嫩、治愈、手绘绘本感；描边与块面都不"干净矢量"，强调手工感。

### 2.2 本集统一色板（HEX）
| 角色 | 色值 |
|---|---|
| 纸张底色（奶白） | `#FBF6EE` |
| 奶油粉（主） | `#F6D3DA` |
| 奶油黄 | `#F7E6B8` |
| 浅木棕 | `#C9A98A` |
| 米白 | `#F3EADF` |
| 淡奶蓝 | `#CFE0E6` |
| 浅玫瑰 | `#EBC3C9` |
| 少量浅灰蓝 | `#AEB9C4` |
| 轮廓线（暖褐，非纯黑） | `#6B5148` |
| 腮红 | `#F0B7BE` |

**禁用**：大面积黑/深蓝/荧光色/高饱和红橙/强对比冷色；3D、写实、扁平矢量、厚涂、赛璐璐、强反光、金属、霓虹。

### 2.3 线条与上色实现原则
- 所有补绘元素统一：**描边宽度 ≈ 人物线条**，描边色 `#6B5148` 附近，边缘加**轻微模糊/纹理**以贴近铅笔水彩感（CSS 滤镜或 SVG 描边 + 噪点），禁止干净硬矢量边。
- 视觉层级：暖暖 ˃ 衣柜/裙子 ˃ 装饰（星星、爱心、便签、胶带）。留白与呼吸感优先。

### 2.4 素材策略（诚实结论 = 关键风险）
- 需求要求"优先同一作者、同一系列的手绘素材包"。经检索：**免费可商用范围内，不存在与"现有暖暖粉彩铅笔水彩 Q 版"同源、且覆盖衣柜/裙子/卧室的成套素材包**。
- **本方案建议**：以 `现有暖暖为唯一风格基准`，
  1. **衣柜、裙子、卧室、便签、箭头、虚线框、波浪线、小皇冠、丝带等** → 用 **SVG/CSS 按 §2.2 色板与 §2.3 线条规范补绘**（需求 §10 明确允许）；
  2. **纸张纹理**、**少量水彩花/蝴蝶结道具** → 采用下述**同一风格倾向、同一色系**的免费可商用真实素材，**仅作点缀**，不混用异风格素材。
- 这样既满足"真实可用免费手绘素材"，又避免"不同网站可爱素材直接混拼"。

## 七、风险与缺口（据实说明）

1. **Spine 表情能力缺失（最高风险）**：无睁眼/微笑/眼神层，`animations` 为空。→ 分镜需按 §1.3 改写，表现力靠头/身动作 + 道具与场景动态承担。
2. **无同源手绘场景素材包**：衣柜/裙子/卧室需 SVG 补绘（工作量在场景绘制，不在人物）。
3. **无 ffmpeg**：不影响 Remotion 渲染；仅个别音频格式转换需处理。
4. **8GB 内存**：全程先低分辨率预览；素材避免同时高清加载。
5. **BGM/音效尚未试听**：仅凭来源与描述筛选，阶段二须实际试听后再定。
